# CampusConnect implementation plan

Each lab is one gated phase. I will commit the completed phase and wait for review before starting the next one.

1. **Phase 1 - Lab 1:** Build the responsive CampusConnect dashboard with semantic HTML, external CSS, mock data, and three JavaScript interactions.
2. **Phase 2 - Lab 2:** Replace the Student Profile, Announcements, and Assignments mock data with JSONPlaceholder `fetch()` calls, error handling, and one filter/refresh interaction. **Complete - awaiting review.**
3. **Phase 3 - Lab 3:** Create the Student REST API: full Express CRUD with validation, errors, OpenAPI documentation, and equivalent Spring Boot GET/POST examples. **Complete - awaiting review.**
4. **Phase 4 - Lab 4:** Persist the Student API in MongoDB, add CORS, make the React CRUD client, and add Android list/create screens against the same API. **Complete - awaiting review.**
5. **Phase 5 - Lab 5:** Dockerize the Student API and MongoDB with environment configuration, volume-backed persistence, and Docker Compose.
6. **Phase 6 - Lab 6:** Split the backend into User, Product, and Order services with Docker networking, service-to-service validation, and Compose orchestration.

Labs 7 and 8 are explicitly out of scope.
